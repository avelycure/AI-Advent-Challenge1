# Контролируемый жизненный цикл задачи

## Состояния и рёбра

У каждой активной ветки диалога есть отдельный конечный автомат:

```text
planning → execution → validation → done
```

Разрешён переход только в тот же или в следующий соседний этап. Переход назад,
пропуск этапа и выход из `done` отклоняются. В отличие от обычной подсказки для
модели эти правила проверяет Python код, поэтому служебная директива модели не
может сама перепрыгнуть через этап.

Состояние хранит:

| Поле | Назначение |
|---|---|
| `stage` | текущий этап |
| `current_step` | конкретная точка работы |
| `expected_action` | следующее ожидаемое действие |
| `paused` | пауза без потери этапа |
| `plan_approved` | явное утверждение плана пользователем |
| `validation_passed` | успешный результат обязательной проверки |
| `validation_evidence` | какие проверки действительно выполнены |

## Контрольные ворота

У двух рёбер есть дополнительные условия:

1. `planning → execution` открывается только после утверждения плана.
2. `validation → done` открывается только после успешной валидации с непустым
   описанием выполненных проверок.

Обычная фраза `Утверждаю план` распознаётся до основного ответа и открывает
первое ребро. Отрицание вроде `Я не утверждаю план` ничего не меняет. Для точной
ручной коррекции есть `/task approve`.

Второе ребро модель может открыть только на этапе `validation`, вернув
`validation_passed=true` и `validation_evidence`. Вручную тот же факт задаётся
командой `/task validate Все обязательные тесты прошли`.

Инструменты недоступны основному ответу, пока план не утверждён. Системная
инструкция требует в `planning` предложить план и запросить утверждение, а в
`validation` выполнить проверку. Если модель всё же возвращает запрещённый
переход, её содержательный ответ не выходит пользователю. Вместо него агент
показывает причину отказа и действие, необходимое для продолжения. Решение также
видно в JSON результата в `task_transition_checks`.

## Автоматическое управление

Первая обычная реплика запускает `planning`. После каждого ответа модель
добавляет скрытую директиву:

```text
[[TASK_STATE {"stage":"validation","current_step":"Проверить результат","expected_action":"Запустить тесты","paused":false,"validation_passed":false,"validation_evidence":""}]]
```

Программа снимает директиву с видимого ответа, проверяет одно разрешённое ребро
и только потом меняет состояние. Если модель оставила `execution` или
`validation`, отдельный короткий контролёр сверяет фактически выполненную работу
и предлагает максимум один следующий этап. Он подчиняется тем же воротам.

## Пауза и восстановление

Пауза меняет только `paused`. Этап, текущий шаг, утверждение плана и результат
валидации сохраняются как есть. Они записываются в файл сессии и копируются в
точки возврата и ветки. После запуска с `--resume` команда `/resume` возвращает
задачу в ту же точку: повторно утверждать план или повторять уже зафиксированную
проверку не требуется.

Старые сохранённые сессии совместимы с новым форматом. Если старая задача уже
находилась в `execution` или дальше, план считается пройденным; для старого
`done` восстанавливается отметка о завершённой проверке.

## Ручные команды

| Команда | Действие |
|---|---|
| `/task` | показать этап, ворота и ожидаемое действие |
| `/task approve` | утвердить план |
| `/task next шаг \| действие` | пройти одно разрешённое ребро |
| `/task validate результат проверки` | зафиксировать успешную валидацию |
| `/pause`, `/resume` | приостановить и продолжить с сохранённого места |
| `/task reset` | очистить жизненный цикл; следующая реплика создаст новый |

## Проверка

`tests/test_task_state.py` проверяет:

1. Полную разрешённую цепочку и оба контрольных условия.
2. Запрет пропуска, возврата, реализации без утверждения и финала без проверки.
3. Замену ответа модели понятным отказом при незаконной директиве.
4. Отличие явного утверждения от отрицательной формулировки.
5. Автоматическое продвижение обычными сообщениями пользователя.
6. Сохранение этапа и открытых ворот после паузы и перезапуска.
7. Независимость веток и работу при отключённой истории.
