# Состояние задачи как конечный автомат

## Что добавлено

У активной ветки диалога теперь есть формализованное состояние задачи:

| Поле | Что хранит |
|---|---|
| `stage` | этап `planning`, `execution`, `validation` или `done` |
| `current_step` | конкретный шаг, на котором остановилась работа |
| `expected_action` | действие, которое должно произойти следующим |
| `paused` | признак паузы без потери остальных полей |

Допустимы только последовательные переходы:

```text
planning → execution → validation → done
```

Автомат не разрешает пропустить проверку, вернуться на предыдущий этап или
продвинуть задачу, пока она на паузе.

## Автоматическое управление

Пользователь даёт задачу обычной репликой. Агент сам создаёт `planning` и
записывает текст задачи как первый текущий шаг. Команда `/task start` для
этого не нужна.

В каждый запрос добавляются текущее состояние и инструкция управлять
автоматом. После содержательного ответа модель возвращает служебную JSON
директиву с новым этапом, шагом, ожидаемым действием и признаком паузы.
Программа скрывает директиву из ответа и применяет её только после проверки:

- этап может остаться прежним или сдвинуться ровно на один вперёд;
- неизвестный этап, переход назад или пропуск этапа отвергается;
- модель может поставить `paused=true`, если ей нужно решение пользователя;
- после `done` переходов больше нет.

`/task` показывает состояние, но не требуется для работы. `/task step`,
`/task next` и названия этапов оставлены как ручная коррекция на случай ошибки
модели. `/task reset` очищает автомат; следующая реплика начинает новую задачу.

Например, для демонстрации достаточно написать:

```text
Создай консольный калькулятор с операциями +, -, *, / и обработкой деления на ноль.
```

Агент сам запускает `planning`, после плана переводит задачу в `execution`,
после реализации — в `validation`, а после проверки — в `done`. `/task` между
ответами нужен только для показа состояния аудитории.

## Пауза и продолжение

Пауза меняет только `paused`. Этап, шаг и ожидаемое действие остаются
неизменными. Состояние записывается в файл сессии даже до первого сообщения,
поэтому после выхода можно вернуться обычной командой `--resume` и выполнить
`/resume`.

Активное состояние добавляется к каждому запросу модели отдельным служебным
сообщением. Пользователю достаточно сказать «Продолжай»: модель уже получает
этап, шаг и ожидаемое действие и не должна заново спрашивать описание задачи.
Это работает и с `--no-history`.

## Ветки

Точка возврата снимает копию автомата вместе с перепиской и рабочей памятью.
Каждая новая ветка начинает с этого снимка, а дальнейшие переходы в одной
ветке не меняют состояние соседней.

## Проверка

`tests/test_task_state.py` проверяет:

1. Полную цепочку переходов и запрет пропуска этапов.
2. Паузу и продолжение на каждом из четырёх этапов.
3. Автоматический запуск от обычной пользовательской задачи.
4. Самостоятельное обновление этапа, шага и следующего действия моделью.
5. Скрытие служебной директивы и отклонение недопустимого перехода.
6. Повторную передачу шага модели после продолжения.
7. Сохранение паузы, независимость веток и работу без истории.
