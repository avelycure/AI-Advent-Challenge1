# План: задавать параметры агента при запуске

## Зачем

Сейчас поведение агента задаёт файл конфига. Хочешь другую модель или ответ
покороче — правь YAML и сохраняй. Это неудобно для разовых запусков и делает
невозможным одноразовый под-агент: под каждую мелочь нужен новый файл.

После работы любое поведение можно будет задать прямо в команде запуска.

## Можно ли подменять дефолтный конфиг при запуске

**Да, любое поле.** Дефолтный конфиг становится основой, а команда
запуска накрывает его сверху. Заданные поля меняются, остальные остаются как
были — включая те, что ты никогда не трогал.

### Кто ты и куда идёшь

| Поле | По умолчанию | Что задаёт |
|---|---|---|
| `name` | `default` | подпись агента: видна в панелях, отчётах и при вызове под-агента |
| `provider` | `openai` | какой сервис из восьми |
| `model` | `gpt-5.4-mini` | какая модель из 26 |
| `system_prompt` | «полезный ассистент…» | кем агент себя считает и как отвечает |
| `api_key` | — | ключ; обычно не задают, он берётся из окружения или файла рядом |
| `api_extra` | — | второй реквизит; нужен только YandexGPT (идентификатор каталога) |

### Как отвечает модель

| Поле | По умолчанию | Что задаёт |
|---|---|---|
| `generation.temperature` | `0.7` | разброс ответов: ниже — предсказуемее, выше — разнообразнее |
| `generation.max_tokens` | резерв модели | предел длины ответа |
| `generation.top_p` | — | доля продолжений, из которых модель выбирает |
| `generation.stop` | — | строки, на которых ответ обрывается |
| `generation.response_format` | — | просить провайдера отвечать строго JSON |

### Что принимается на вход

| Поле | По умолчанию | Что задаёт |
|---|---|---|
| `input.max_chars` | `8000` | максимальная длина запроса |
| `input.on_too_long` | `reject` | длинный запрос отклонить (`reject`) или обрезать (`trim`) |
| `input.template` | — | обёртка вокруг каждого запроса: `Переведи на английский: {input}` |
| `input.forbidden` | пусто | слова, при которых запрос не уйдёт в модель и не будет стоить денег |
| `input.forbid_empty` | да | отклонять пустой запрос |
| `input.strip` | да | убирать пробелы по краям |

### Какой ответ считается годным

| Поле | По умолчанию | Что задаёт |
|---|---|---|
| `output.format` | `free` | `free` — любой текст, либо `json`, `yaml`, `md` |
| `output.max_attempts` | `1` | сколько раз переспросить модель, если форма не та |
| `output.require_valid` | нет | не сошлось — вернуть ошибку вместо негодного ответа |
| `output.stop_marker` | — | договорный маркер конца ответа |
| `output.strip_fence` | да | снимать тройные кавычки, если модель их добавила |
| `output.schema.fields` | пусто | какие поля должны быть в ответе, каких типов и в каких пределах |
| `output.schema.item_count` | — | сколько элементов должно быть ровно |
| `output.schema.key` | `items` | под каким ключом лежит список |
| `output.schema.allow_extra_fields` | нет | терпеть ли лишние поля |

### Проверка ответа судьёй

| Поле | По умолчанию | Что задаёт |
|---|---|---|
| `judge` | нет судьи | включить оценку ответа отдельной моделью |
| `judge.criteria` | полнота, ясность, обоснованность | по каким признакам оценивать |
| `judge.min_mean` | — | порог: ниже него ответ помечается слабым |
| `judge.scale` | `5` | шкала оценки |
| `judge.max_tokens` | `200` | предел длины ответа судьи |
| `judge.agent` | та же модель | отдельный конфиг судьи — можно другой провайдер |

### Память и деньги

| Поле | По умолчанию | Что задаёт |
|---|---|---|
| `history.enabled` | да | помнить диалог или отвечать каждый раз с чистого листа |
| `history.keep_last_answer` | да | из нескольких ответов на один вопрос отправлять последний |
| `budget.max_cost` | без предела | потолок трат за сессию; дойдя до него, агент откажется отправлять запрос |
| `budget.max_tokens` | без предела | потолок токенов за сессию |
| `budget.max_requests` | без предела | потолок числа запросов |
| `transport.demo` | нет | заглушка вместо сети: всё работает, денег не тратится |
| `transport.demo_delay` | как живая | длина паузы заглушки |

## Три способа задать

### 1. Готовым конфигом

```bash
agent --config frugal
```

Как сейчас: короткое имя из `configs/` или путь к файлу.

### 2. Конфигом прямо в команде

```bash
agent --config '{"model": "gpt-5.4-nano", "budget": {"max_cost": 0.01}}' --ask "..."
```

Новое. Файл под разовый запуск больше не нужен.

### 3. Флагом или `--set`

У частых полей будет короткий флаг:

| Флаг | Поле |
|---|---|
| `--model gpt-5.4` | модель (провайдер определится сам) |
| `--provider groq` | сервис |
| `--temperature 0.2` | разброс ответов |
| `--max-tokens 300` | предел длины ответа |
| `--system-prompt "…"` | кем агент себя считает |
| `--append-system-prompt "…"` | дописать к действующему промпту |
| `--format json` | требуемая форма ответа |
| `--max-cost 0.05` | потолок трат |
| `--no-history` | отвечать без памяти |
| `--name "черновик"` | подпись агента |
| `--session-id abc123` | свой идентификатор сессии |

Остальные поля задаются `--set поле=значение`, повторяемым сколько нужно:

```bash
agent --set output.max_attempts=3 --set input.on_too_long=trim --set judge.min_mean=4
```

Длинный список флагов вреден: справку перестают читать. Флаги — только на то,
что набирают часто, `--set` — на всё остальное.

## Что победит, если задать одно поле дважды

От общего к частному: **конфиг → флаг → `--set`**.

```bash
agent --config frugal --temperature 0.2 --set generation.temperature=0.9
#            ↑ 0.2 из файла      ↑ станет 0.2        ↑ станет 0.9
```

`--set` последний потому, что это самое явное указание: человек назвал поле
полным путём и явно знает, чего хочет.

## Проверить, что получилось

```bash
agent --config frugal --temperature 0.2 --show-config
```

Печатает собранный конфиг целиком и выходит. Нужен именно из-за слоёв: без
него порядок пришлось бы проверять на глаз. Ключ в выводе заменён на `***`,
конфиг можно показывать и пересылать.

## Живые сценарии

| Хочу | Команда |
|---|---|
| ответ подешевле и покороче | `agent --model gpt-5.4-nano --max-tokens 150` |
| строго JSON, и чтобы переспросил, если не так | `agent --format json --set output.max_attempts=3` |
| проверить ответ судьёй с порогом | `agent --set judge.min_mean=4` |
| не тратить больше пяти центов | `agent --max-cost 0.05` |
| каждый вопрос сам по себе, без памяти | `agent --no-history` |
| переводчик из одного запроса | `agent --set input.template="Переведи на английский: {input}"` |
| один вопрос из скрипта | `agent --ask "…" --json` |
| порепетировать бесплатно | `agent --demo` |

## Под-агенты с правками

Сейчас под-агенту можно дать только готовый конфиг из `configs/`. Станет можно
править его на месте:

```
/agent frugal temperature=0.1 max_tokens=80 -- Что такое хороший код
```

До `--` правки, после — вопрос. Без `--` всё после имени остаётся вопросом,
то есть привычное поведение не меняется.

## Сессии

`--session-id` и `--name` дают сессии адрес и подпись — их видно в шапке и в
выводе `--json`. Памяти это не добавляет: **два запуска с одним `--session-id`
остаются двумя разными сессиями с пустой памятью.** Идентификатор нужен, чтобы
связать записи между собой, а не чтобы вернуться в разговор.

## Возврат в прошлую сессию — отдельное решение

`--continue` и `--resume`, как у Claude Code, **противоречат твоему прежнему
выбору**: вернуться в разговор нельзя, не сохранив его на диск, а по сессиям
ты выбрал «только в памяти процесса».

Что изменится, если всё же делать: появится каталог `~/.llm-agent/sessions/`,
и переписка со всеми вопросами и ответами будет лежать там файлами до тех пор,
пока ты их не удалишь. Плюс команда `--sessions` со списком. Отдельного «да»
жду именно из-за переписки на диске, а не из-за объёма работы.

Всё остальное в этом плане от этого пункта не зависит.

## Порядок работ

После каждого шага появляется что-то, чем можно пользоваться.

| № | Шаг | Что становится можно |
|---|---|---|
| 1 | `--set поле=значение` | задать при запуске любое поле конфига |
| 2 | короткие флаги | не набирать полный путь для частого |
| 3 | `--show-config` | увидеть, что получилось из всех слоёв |
| 4 | `--config` строкой | разовый конфиг без файла |
| 5 | правки под-агенту | `/agent frugal temperature=0.1 -- вопрос` |
| 6 | `--session-id`, `--name` | своё имя и адрес у сессии |
| 7 | справка и README | `--help` показывает всё перечисленное |
| 8 | *по отдельному «да»* | `--continue`, `--resume`, `--sessions` |

## Что не будет сделано

**Настроек, подхватываемых из текущего каталога, не появится.** У Claude Code
настройки собираются из трёх мест сразу — домашнего каталога, каталога проекта
и локального файла. Для нашего инструмента это лишнее: конфиг ты называешь
руками, и агент, меняющий поведение от того, из какой папки его запустили,
скорее удивит, чем поможет.

**Опечатка в имени поля будет ошибкой, а не тишиной.** `--set outupt.format=json`
скажет, что такого поля нет, и перечислит, какие есть. Иначе правка молча
не применилась бы, а ты решил бы, что агент её проигнорировал.
