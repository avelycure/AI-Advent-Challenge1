# День 9. Сжатие истории — план

## Что уже есть к началу дня

| Требование дня 9 | Состояние |
|---|---|
| хранить последние N сообщений как есть | ⚠️ в запрос уходит вся переписка целиком |
| остальное заменять пересказом | ❌ нечем: день 8 прямо отказался от сжатия |
| хранить пересказ отдельно и подставлять вместо истории | ❌ |
| сравнить расход токенов до и после | ⚠️ есть чем мерить (`/tokens`, `./tokens.sh`), но не с чем сравнивать |
| сравнить качество ответов | ❌ |
| включать и выключать сжатие конфигом | ❌ |

Что уже работает и пригодится: подсчёт токенов по частям запроса, поправка на
чужой токенизатор, суженное окно (`history.window`), отказ и обрезка при
переполнении (`history.on_overflow`), сохранение сессии в JSON.

## Что не так сегодня

| Что не так | Чем мешает |
|---|---|
| каждый вопрос отправляет всю переписку заново | десятый вопрос стоит вчетверо дороже первого при той же длине |
| единственный способ уместиться в окно — забыть начало | вместе с началом теряются имя, условие задачи и договорённости |
| длинный разговор упирается в окно и встаёт | продолжать можно только с потерей памяти |

## Что появится

| Что человек получит | Как выглядит |
|---|---|
| последние N сообщений уходят в модель как есть | N задаётся конфигом, по умолчанию 6 |
| всё, что старше, заменяется одним пересказом | пересказ пишет та же модель, отдельным запросом |
| пересказ хранится отдельно и виден | команда `/summary`, сохраняется вместе с сессией |
| сжатие включается и выключается | `--no-compress` — работать со всей историей, как раньше |
| порог сжатия задаётся | сжимать, когда накопилось 10 несжатых сообщений (по умолчанию) |
| сжать прямо сейчас | команда `/compress`, не дожидаясь порога |
| видно, что сжатие дало | в `/tokens` строка «Пересказ начала» и сколько токенов сэкономлено |
| сравнение трёх способов рядом | `./compress.sh`: вся история, обрезка, сжатие |

## Настройки

| Поле конфига | По умолчанию | Что задаёт |
|---|---|---|
| `history.compression.enabled` | `true` | сжимать ли историю вообще |
| `history.compression.keep_last` | `6` | сколько последних сообщений уходит в модель дословно |
| `history.compression.every` | `10` | сколько несжатых сообщений должно накопиться до сжатия |
| `history.compression.max_tokens` | `400` | предел длины самого пересказа |

Флаги запуска: `--no-compress`, `--compress`, `--keep-last N`, `--compress-every N`.
Любое поле доступно и через `--set history.compression.keep_last=4`.

Без единого флага агент работает со сжатием и умолчаниями выше: короткий
разговор ничего лишнего не тратит — сжатие включается только когда накопилось
16 сообщений (8 обменов).

## Шаги

После каждого шага — что должно получиться и как это проверяется.

| № | Шаг | Проверка |
|---|---|---|
| 1 | настройки сжатия в конфиге | `--show-config` показывает раздел, негодные значения отвергаются при запуске |
| 2 | переписка умеет хранить пересказ отдельно от сообщений | пересказ переживает сохранение и возврат в сессию |
| 3 | в запрос уходит пересказ плюс последние N сообщений | сжатое начало в модель не идёт, на экране остаётся видимым |
| 4 | пересказ пишет модель отдельным запросом | расход этого запроса виден в `/stats` отдельной строкой |
| 5 | сжатие срабатывает само при накоплении порога | после 8 обменов вход следующего запроса меньше, чем был |
| 6 | сжатие можно выключить | `--no-compress` — поведение дня 8 без изменений |
| 7 | `/summary` и `/compress` в чате | пересказ видно и можно обновить руками |
| 8 | `/tokens` показывает выгоду | строка «Пересказ начала» и сколько сэкономлено |
| 9 | `./compress.sh` — три способа рядом | вся история, обрезка, сжатие: токены, деньги, память |
| 10 | краевые случаи | ниже отдельным списком |
| 11 | обзор кода, тесты, документация | замечания разобраны, набор тестов зелёный |

## Краевые случаи

| Случай | Ожидаемое поведение |
|---|---|
| разговор короче порога | сжатия не происходит, лишних запросов нет |
| запрос на пересказ не удался | ответ на вопрос всё равно даётся, историю не теряем, о неудаче сказано |
| сжимать нечего дважды подряд | второй раз запрос к модели не уходит |
| пересказ сам вырос до размера истории | пересказывается вместе с новыми сообщениями, а не копится |
| сжимаемый кусок больше окна | пересказывается частями, по куску за раз |
| граница попала внутрь обмена | граница сдвигается назад: вопрос и ответ на него не разлучаются |
| сжатия не хватило, окно всё равно полно | дальше работает прежняя политика: отказ или обрезка |
| обрезка при уже сжатом начале | выбрасываются те сообщения, что действительно уходят в модель, а не уже сжатые |
| смена модели посреди разговора | пересказ остаётся: это текст, а не измерение чужим токенизатором |
| `/new` и сброс диалога | пересказ забывается вместе с историей |
| файл сессии от прежней версии | читается, пересказа в нём просто нет |

## Как сравниваем

`./compress.sh` ведёт один и тот же разговор тремя способами и показывает
итоги рядом.

| Способ | Что делает | Чего ждём |
|---|---|---|
| вся история | отправляет всю переписку каждый раз | дороже всех, при узком окне встаёт |
| обрезка | забывает начало, чтобы влезть | дёшево, но имя из первого вопроса потеряно |
| сжатие | пересказ плюс последние N сообщений | дешевле полной истории, имя помнит |

Качество меряется проверкой памяти: имя названо в первом вопросе, факт — в
середине разговора, оба спрашиваются в конце. Ответ засчитывается, если
названное в нём совпадает с тем, что было сказано. Расход берётся из счётчиков
агента: вход, выход, число запросов, деньги.

Без `--live` всё идёт на заглушке и не стоит ничего.

## Чего делать не буду

**Своего пересказчика без модели не будет.** Выжимка по частотам слов не
сохраняет ни имён, ни договорённостей, а ради экономии на одном запросе
терять смысл разговора незачем.

**Векторной памяти и поиска по прошлым сообщениям не будет.** Это отдельная
задача (RAG), и она не про управление контекстом.

**Пересказ не будет пересказывать сам себя по кругу.** Прежний пересказ входит
в новый запрос как исходный материал — но отдельного «пересказа пересказов»
с собственной глубиной не заводится.
