# День 6. Требования к агенту и состояние проекта

Первые два раздела — разбор состояния **до** работы, он оставлен как есть.
Что стало после реализации — в последнем разделе.

Требования собраны из трёх источников: формулировка задания, подтверждённое
ментором сообщение про «коробку» с политиками и судьёй, отдельная реплика про
подсчёт токенов и конфиг, проверочный вопрос про 100 агентов.

## Почему 100 агентов сейчас не заспавнить

| Блокер | Файл |
|---|---|
| Настройка интерактивная: провайдер, ключ и модель спрашиваются у человека через `Console` | `app.setup`, `ui.choose_provider`, `ui.ask_token`, `ui.choose_model` |
| Пул клиентов требует `Console` и умеет спрашивать реквизиты в процессе | `switching.ClientPool.ready_for` |
| Нет конструктора вида `Agent(config)` — агента не из чего создать | — |
| Конфиг не выражается данными: нет dict/JSON/YAML описания и загрузчика | — |
| Клиент синхронный и блокирующий, параллельного запуска нет ни на потоках, ни на asyncio | `client.LLMClient.complete` |
| Сценарий — бесконечный цикл по stdin, один процесс = один диалог | `app.chat_loop` |
| Тестов нет ни одного, спавн даже нечем проверить | — |
