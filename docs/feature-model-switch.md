# feature/model-switch — модель меняется во время диалога

Ветка отведена от `feature/reasoning`, поэтому сравнение ниже — разница именно
с ней.

## Коротко

Раньше модель выбиралась один раз, на третьем шаге настройки, и жила до конца
работы программы. Чтобы задать тот же вопрос другой модели, приходилось выходить
и запускать программу заново — а вместе с ней терялась история и счётчики.
Теперь модель и провайдер переключаются прямо в диалоге, история остаётся на
месте, и один вопрос можно прогнать по нескольким моделям подряд.

| | Было | Стало |
|---|---|---|
| Выбор модели | один раз при запуске | `/change_model` в любой момент |
| Смена провайдера | только перезапуском | тем же `/change_model`, ключ спрашивается один раз |
| Повтор вопроса | скопировать и вставить заново | `/retry` |
| Подпись ответа | текущая модель сессии | модель, которая этот ответ написала |
| Время запроса | не измерялось | под каждым ответом |
| Стоимость | не считалась | под каждым ответом и итогом в нижней строке |
| Токены размышления | не были видны | отдельной строкой, если модель их вернула |
| История при смене | терялась вместе с процессом | сохраняется целиком |

## Команды

| Команда | Что делает |
|---|---|
| `/change_model` | список всех моделей всех провайдеров с номерами; текущая — жёлтым |
| `/change_model 4` | переключиться по номеру |
| `/change_model gpt-5.5` | то же по имени модели |
| `/change_model openai gpt-5.5` | если имя есть у нескольких провайдеров |
| `/retry` | задать последний вопрос ещё раз на текущей модели |

Псевдонимы `/model` и `/models` делают то же, что `/change_model`.

## Типичный прогон

```
Вы › Приведи список наиболее успешных книг Нассима Талеба.
🤖 deepseek-chat      …ответ…
Вы › /change_model 4
🔀 Было DeepSeek · deepseek-chat → Стало ChatGPT (OpenAI) · gpt-5.5
Вы › /retry
🤖 gpt-5.5            …ответ на тот же вопрос…
Вы › /history
```

В переписке два ответа на один вопрос стоят рядом и подписаны разными моделями.

## Что изменилось в коде

| Файл | Изменение |
|---|---|
| `llmchat/switching.py` | новый: каталог моделей, разбор аргумента, `ClientPool` с кешем ключей |
| `llmchat/session.py` | `Message` хранит `model` и `accent`; `switch_to`, `api_messages_upto`, `keep_last_answer` |
| `llmchat/app.py` | команды `/change_model` и `/retry`; запрос к модели вынесен в `request_answer` и переиспользуется повтором |
| `llmchat/ui.py` | подпись ответа берётся из сообщения; панели ввода ключа получили заголовок без «Шаг N»; подпись метрик под ответом и цена в нижней строке |
| `llmchat/providers.py` | цены моделей ChatGPT, флаг бесплатного тарифа, функция `request_cost` |
| `llmchat/client.py` | секундомер вокруг запроса, разбор reasoning- и cached-токенов |

`setup()` теперь принимает необязательный `pool`, но возвращает прежнюю
четвёрку — `compare.py` и `reasoning.py` продолжают работать без правок.

## Четыре решения и их причины

**Подпись ответа хранится в сообщении, а не берётся из сессии.** Иначе после
переключения все прежние ответы переклеились бы именем новой модели — ровно то,
ради чего затевалось сравнение, перестало бы работать.

**`/retry` отрезает всё, что было отвечено после вопроса.** Иначе новой модели
досталась бы задача «продолжи за коллегой», а не исходный вопрос. Задача должна
быть одна и та же, иначе сравнение нечестное.

**Подряд идущие ответы схлопываются при отправке.** В переписке видны все, но в
обычный следующий запрос уходит только последний: модель не должна получать три
ответа на один свой вопрос.

**Точный счёт контекста сбрасывается при смене.** Размер диалога известен из
`usage` ответа, но измерен токенизатором прежней модели. После смены он неверен,
поэтому история снова оценивается локально — приблизительно, зато одним способом.

## Ограничения

- Параметры генерации при смене модели сохраняются. Если новая модель не примет
  какой-то из них, сработает прежний механизм: параметр убирается из запроса,
  и об этом появляется панель. Так ведут себя GPT-5.5 и GPT-6 Astra
  с `temperature`: сравнивать их с остальными по случайности не получится.
- История может не поместиться в окно новой модели — тогда панель перехода
  говорит об этом красным, и следующий вопрос не примется до `/new`.
- Счётчик расхода токенов общий на всю сессию и по моделям не разбит: сумма
  по каждой модели отдельно не считается, хотя цена каждого ответа видна.
- Цены заданы только у моделей ChatGPT и у бесплатных тарифов Groq и
  OpenRouter. У остальных провайдеров показывается прочерк, а итог сессии
  помечается знаком `≥`.
