# Ветка `feature/context-persistence` — сохранение контекста

Задание дня 7: хранить историю диалога, загружать её при перезапуске и
продолжать разговор так, будто агент не выключался.

План и краевые случаи — [day7-context-plan.md](day7-context-plan.md).

## Чем эта реализация отличается от предыдущей

**Половина задания была закрыта уже в дне 6**, и это стоит сказать прямо.
История лежала в JSON, `--continue` и `--resume` её возвращали, разговор
продолжался. Проверка «начните диалог → перезапустите → продолжите»
проходила и до этой ветки.

Не хватало другого — того, на что и был отдельный упор в задании: **чтобы
этим было удобно человеку**. Сессия звалась `9402e5d1`, в списке стояла
колонка «Тема», которую придумывала модель и которая бывала пустой, а имени
у самой сессии не было вовсе.

| Было | Стало |
|---|---|
| сессия зовётся `9402e5d1` | у сессии своё имя: `--name`, `/rename`, а без них придумывается само |
| поле `name` — это имя конфига | имя сессии и имя агента разведены: `title` и `agent` |
| в списке номер, модель, токены | номер, имя, когда, обменов и **первый вопрос** |
| `--resume` только по идентификатору | по номеру из списка, по имени и по части идентификатора |
| `--resume` требует аргумент | без аргумента предлагает выбрать из списка |
| списка не найти в десятке сессий | `--sessions слово` ищет по именам, темам и **тексту переписки** |
| удаление только по идентификатору | по имени и номеру тоже |
| два терминала в одной сессии молча затирали друг друга | сессия отделяется, ни один разговор не теряется |

## Ключевые решения

**Имя придумывается само.** Пустая подпись в списке бесполезна, а тему модель
уже сочиняет в три-пять слов — она и становится именем. Пока темы нет, годится
начало первого вопроса: по нему разговор узнаётся вернее всего.

**Поиск смотрит внутрь переписки.** Через неделю человек помнит, о чём говорил,
а не как назвал сессию. Поэтому `--sessions Дейкстры` находит разговор по слову
из середины диалога, а не только по имени.

**Неоднозначность — вопрос, а не выбор за человека.** Если под имя подходят
несколько сессий, программа перечисляет их и просит уточнить номером. Молча
взять первую значило бы продолжить не тот разговор.

**Два терминала не теряют работу.** Открыть одну сессию дважды легко одной
командой `--continue`. Прежде второй терминал молча затирал первого: проверено,
из файла пропадал целый вопрос с ответом. Теперь при записи сверяется время
последней правки, и если файл успел измениться — разговор продолжается
отдельной сессией, о чём человеку говорится прямо. Допуск в полсекунды
намеренный: у времени изменения файла грубая точность, и без допуска сессия
отделялась бы от самой себя после каждого ответа.

**Прежние файлы читаются.** До этой ветки в поле `name` лежало имя конфига.
Такие файлы не теряют подпись: старое поле читается как имя агента, а имя
сессии выводится из первого вопроса.

## Что нашёл обзор кода

Полный обзор диффа дал двадцать одно замечание, из них пятнадцать значимых.
Ни одно не ловилось тогдашними тестами. Самые дорогие:

| Что было не так | Чем это грозило |
|---|---|
| номер в списке поиска считался заново, а команды брали номер от полного списка | `--sessions Борщ` показывал «1», а `--rm-session 1` удалял **другой разговор** |
| допуск в полсекунды при сверке времени записи | чужая запись в те же полсекунды пропадала молча — ровно то, от чего защищались |
| `/new` оставлял прежнее имя | оба разговора звались одинаково и становились неразличимы |
| `/retry` не сохранялся | переспрошенный ответ терялся при выходе |
| размер контекста брался после круга инструментов | окно объявлялось полным на втором вопросе, и вопрос выбрасывался |
| итог не включал круги инструментов | под-агент недоговаривал вызвавшему вдвое, и бюджет считался по половине |
| `--provider` и `--model` без `--config` затирались расспросом | документированная бесплатная команда открывала «Шаг 1» и уходила к DeepSeek |
| `--set input.forbidden=пароль` рассыпался на буквы | запрещённой оказывалась каждая буква, и русский текст не проходил вовсе |
| обрамление вставки срезалось по всему тексту | `curl "http://x/?v=201~2"` терял хвост — текст молча портился |
| в `--json` попадали рамки и трассировки | вызывающий видел «под-агент не вернул JSON» вместо причины |
| идентификатор из одних цифр читался как номер | такая сессия не открывалась по тому идентификатору, который ей показывают |
| логическое поле в таблице Markdown не приводилось | верный ответ жёг все переспросы за настоящие деньги |

Отдельно нашлась причина случайных падений набора тестов: дочерний процесс
после `pty.fork()` при неудачном запуске продолжил бы выполнять тесты вторым
процессом, а сами процессы никто не хоронил. Теперь ребёнок выходит сам, а
терминал дожидается его конца.

Дважды за этот заход я повторил одну и ту же ошибку — угадывал поле конфига по
имени, не глядя на раздел. Сначала `enabled` у истории превратился в перечень
инструментов, потом то же случилось при разборе правок. Оба раза чинилось
одинаково: разрешать по владельцу, а не по имени.

## Чего не делал

**SQLite не появился.** Задание допускает JSON, а файл на сессию лучше для
человека: его видно в каталоге, можно прочитать глазами, скопировать и удалить
без инструментов.

**Синхронизации между машинами нет.** Это отдельная задача, и она не про
сохранение контекста.
