# Персонализация ассистента

## Что добавлено

Поверх долговременной памяти появился `UserProfile`. Он хранится в прежнем
`~/.llm-agent/memory/profile.json`, поэтому профиль общий для проектов и переживает
новый диалог, перезапуск и смену стратегии контекста.

Профиль разделён по назначению:

| Префикс | Что описывает | Пример |
|---|---|---|
| `identity.*` | обращение и язык | `identity.address=Иван` |
| `style.*` | тон и подробность | `style.tone=кратко` |
| `format.*` | структура ответа | `format.answer=Markdown` |
| `constraints.*` | постоянные ограничения | `constraints.no_push=только по команде` |
| `task.<имя>.*` | процесс для типа задачи | `task.feature.instructions=сначала план` |
| `domain.<имя>.*` | поведение в предметной области | `domain.shopping.instructions=сравни цены` |

## Настройка

```text
/profile identity.address=Иван
/profile style.tone=коротко и по делу
/profile format.answer=сначала вывод, затем детали
/profile constraints.no_push=не выполнять push без явной команды

/profile task.feature.match=напиши фичу,реализуй фичу
/profile task.feature.instructions=сначала исследователь, затем два исполнителя

/profile domain.shopping.match=собери корзину,подбери товары
/profile domain.shopping.instructions=сравни цену, рейтинг и доставку
```

Пустое значение удаляет настройку. `/profile` без аргументов показывает память.
Старая команда `/memory long profile ключ=значение` работает как раньше.

## Как профиль применяется

Перед каждым ответом агент получает текущий пользовательский вопрос. Общая часть
профиля добавляется всегда. Для `task` и `domain` агент сравнивает вопрос с
фразами из `match` без учёта регистра и добавляет только совпавшие секции.

Например, «Напиши фичу импорта» получает процесс `task.feature`, а следующий
вопрос «Собери корзину для пикника» получает правила `domain.shopping`. Стиль и
формат пользователя действуют в обоих запросах автоматически.

Профиль остаётся включённым при `--no-history`: этот флаг убирает прошлые реплики,
working-memory и память проекта, но пользователь по-прежнему получает привычный
стиль ответа.

## Проверка

`tests/test_profile.py` проверяет четыре наблюдаемых свойства:

1. Один запрос получает разные ответы для двух профилей.
2. Стиль, формат и ограничения присутствуют в каждом запросе.
3. Правила разработки и покупок выбираются автоматически и не смешиваются.
4. `/profile` сохраняет данные в долговременное хранилище.
