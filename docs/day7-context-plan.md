| Требование дня 7 | Состояние |
|---|---|
| хранить историю диалога в JSON | ✅ `~/.llm-agent/sessions/<id>.json` |
| при перезапуске загружать историю обратно | ✅ `--continue`, `--resume` |
| продолжать диалог как будто не выключались | ✅ вся переписка уходит в модель |

Проверка «начните диалог → перезапустите → продолжите» проходит уже сейчас.
SQLite не нужен: задание допускает JSON, а один файл на сессию проще читать
глазами и удалять руками.

## Что на самом деле надо сделать

Отдельное требование — чтобы этим было **удобно человеку**. Вот здесь дыры.

| Что не так сегодня | Чем мешает |
|---|---|
| сессия зовётся `9402e5d1` | не запомнить, не назвать вслух, не набрать по памяти |
| колонка «Тема» бывает пустой или общей | из списка не понять, о чём был разговор |
| поле `name` — это имя конфига, а не сессии | в списке нет имени самой сессии |
| нет первого вопроса в списке | приходится заходить в сессию, чтобы вспомнить |
| нельзя переименовать | имя, придуманное моделью, останется навсегда |
| нельзя найти по слову | при десятке сессий список бесполезен |
| `--resume` только по идентификатору | номер из списка не работает |

## Шаги

После каждого шага — что должно получиться и как это проверяется.

| № | Шаг | Проверка |
|---|---|---|
| 1 | у сессии появляется своё имя, отдельное от имени конфига | `--name "Алгоритмы"` виден в шапке и в списке |
| 2 | имя придумывается само, если не задано | из темы разговора или из первого вопроса |
| 3 | `/rename` меняет имя в работающем диалоге | список показывает новое имя |
| 4 | в списке видно, о чём был разговор | имя, первый вопрос, когда, сколько обменов |
| 5 | `--resume` принимает номер из списка, имя и часть идентификатора | все три способа ведут в ту же сессию |
| 6 | `--resume` без аргумента предлагает выбрать | список с номерами и вопрос «какую?» |
| 7 | `--sessions <слово>` ищет по именам, темам и тексту переписки | находит сессию по слову из середины разговора |
| 8 | краевые случаи | ниже отдельным списком |
| 9 | обзор кода и правки | замечания разобраны |
| 10 | ручное тестирование | сценарий из задания пройден руками |

## Краевые случаи

| Случай | Ожидаемое поведение |
|---|---|
| два терминала пишут одну сессию | второй не затирает первого молча |
| файл сессии испорчен | пропускается в списке, остальные читаются |
| файл от прежней версии, без нового поля | читается, имя придумывается на ходу |
| имена совпали | обе сессии доступны, различаются идентификатором |
| очень длинная переписка | список не тормозит, имя не разъезжается |
| имя из пробелов или пустое | отвергается с понятным текстом |
| `--resume` по неоднозначному куску имени | просит уточнить и показывает подходящие |
| удаление по имени, а не по идентификатору | работает так же |

## Чего делать не буду

**SQLite не появится.** Задание допускает JSON, а файл на сессию лучше для
человека: его видно в каталоге, можно прочитать глазами, скопировать и удалить
без инструментов.

**Сессии не будут сливаться между машинами.** Синхронизация — отдельная задача,
и она не про сохранение контекста.
