# День 8. Работа с токенами — план

## Что уже есть к началу дня

| Требование дня 8 | Состояние |
|---|---|
| токены ответа модели | ✅ подписаны под каждым ответом: вход → выход, размышление, цена |
| токены всей истории | ✅ полоса «Контекст» в шапке и `/stats` |
| токены текущего запроса | ⚠️ считаются внутри, только ради лимита; человеку не показываются |
| рост токенов и денег по ходу диалога | ❌ виден только итог, не видно, как он набегал |
| сравнение короткого, длинного и переполненного диалога | ❌ нечем сравнивать |
| что ломается при переполнении | ⚠️ чат отказывается принять сообщение — и всё |

## Что не так сегодня

| Что не так | Чем мешает |
|---|---|
| перед отправкой не видно, из чего сложится запрос | непонятно, что дороже: системный промпт, старая история или новый вопрос |
| счётчик показывает только итог | не видно, что каждый следующий вопрос дороже предыдущего |
| оценка неотправленного считается токенизатором ChatGPT для любой модели | на кириллице и на чужих моделях цифра врёт, а насколько — не сказано |
| переполнение упирается в отказ интерфейса | сам агент про предел ничего не знает: под-агент и `--json` уедут в ошибку провайдера |
| проверить переполнение можно только на 131 000 токенов | бесплатный тариф раньше упрётся в свой лимит, и проверка не состоится |

## Шаги

После каждого шага — что должно получиться и как это проверяется.

| № | Шаг | Проверка |
|---|---|---|
| 1 | агент говорит, из чего сложится ближайший запрос | системный промпт, история, новый вопрос, резерв под ответ, итог — числами |
| 2 | видно, насколько врёт оценка | после ответа рядом стоят «оценили» и «насчитал провайдер», и поправка в процентах |
| 3 | видно рост по обменам | таблица: обмен, вход, выход, весь контекст, цена шага, цена итогом |
| 4 | окно можно сузить при запуске | `--set history.window=4000` — переполнение достижимо без трат |
| 5 | агент сам отказывает при переполнении | понятная ошибка с числами вместо ошибки провайдера |
| 6 | при переполнении можно не падать, а забыть старое | `--set history.on_overflow=trim` — диалог продолжается без начала |
| 7 | команда `/tokens` в чате | шаги 1–3 на экране одной командой |
| 8 | `./tokens.py` — сравнение трёх диалогов | короткий, длинный, переполненный: цифры рядом |
| 9 | краевые случаи | ниже отдельным списком |
| 10 | обзор кода, тесты, документация | замечания разобраны, набор тестов зелёный |

## Краевые случаи

| Случай | Ожидаемое поведение |
|---|---|
| диалог ещё пуст | раскладка показывает только системный промпт, без деления на ноль |
| модель сменили посреди диалога | точная цифра забывается, оценка считается заново, поправка сбрасывается |
| суженное окно меньше резерва под ответ | сообщение об этом при запуске, а не молчаливый бюджет в один токен |
| обрезка не помогает: один вопрос длиннее окна | отказ, а не бесконечная обрезка до пустой истории |
| обрезка выбросила бы системный промпт | системный промпт не трогается никогда |
| провайдер не вернул `usage` | оценка остаётся оценкой, поправка не показывается |
| ответ упёрся в `max_tokens` | сказано, что ответ обрезан, и что это не переполнение контекста |

## Чего делать не буду

**Сжатия истории моделью не будет.** Пересказать старое начало отдельным
запросом — отдельная задача со своей ценой, и она не про подсчёт токенов.

**Своего токенизатора под каждую модель не будет.** У Qwen, GLM и YandexGPT
токенизаторы разные и в открытом виде есть не у всех. Вместо точности —
честность: показывается, чем считали и насколько ошиблись.
