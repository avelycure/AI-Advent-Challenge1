# AI-Advent-Challenge1 — терминальный чат с LLM

Минимальный, но полноценный CLI-клиент к четырём моделям — **DeepSeek**,
**ChatGPT (OpenAI)**, **YandexGPT** и **GigaChat**: отправляет запрос в LLM
через API, получает ответ и показывает его в терминале.

Диалог живёт долго: вся переписка — и реплики пользователя, и ответы модели —
отправляется в LLM при каждом запросе, поэтому модель помнит контекст разговора.

## Что умеет

- **Выбор LLM при старте** — четыре провайдера, со ссылкой на страницу выдачи токена.
- **Запрос токена** — ввод скрыт, ключ никуда не сохраняется. Если в окружении есть
  `DEEPSEEK_API_KEY` / `OPENAI_API_KEY`, программа предложит взять ключ оттуда.
- **Проверка ключа до начала диалога** — понятное сообщение вместо стектрейса, с повтором ввода.
- **Полная история диалога** — контекст накапливается и уходит в модель целиком.
- **Тема диалога в шапке терминала** — формулируется самой LLM после первого ответа
  и обновляется каждые 5 обменов, если разговор ушёл в сторону.
- **Лоадер во время ожидания** — анимированный спиннер с именем модели.
- **Счётчики внизу экрана** — заполнение контекстного окна полосой и процентом,
  сколько токенов свободно, на сколько ещё сообщений хватит места до конца диалога,
  сколько токенов потрачено за сессию и сколько было запросов к API.
- **Защита от переполнения** — предупреждение на подходе к лимиту и отказ отправить
  сообщение, которое уже не помещается в окно модели.
- **Адаптивная вёрстка** — кадр подстраивается под размер терминала, старые сообщения
  сворачиваются, чтобы шапка с темой всегда оставалась наверху.

## Запуск

```bash
./run.sh
```

Скрипт сам создаёт виртуальное окружение, ставит зависимости и запускает чат.
Нужен Python 3.8+ (проверено на системном Python 3.9 из macOS).

Вручную:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python chat.py
```

### Режим проверки без сети

```bash
./run.sh --demo
```

Ответы формирует локальная заглушка, запросы в интернет не уходят — удобно посмотреть
интерфейс и логику счётчиков, не тратя токены. Ключ в этом режиме можно ввести любой.

## Провайдеры и где взять доступ

| Провайдер | Что нужно | Где получить |
|---|---|---|
| DeepSeek | API-ключ | https://platform.deepseek.com/api_keys |
| ChatGPT (OpenAI) | API-ключ | https://platform.openai.com/api-keys |
| YandexGPT | API-ключ **и** идентификатор каталога | https://yandex.cloud/ru/docs/iam/operations/api-key/create |
| GigaChat | ключ авторизации (меняется на токен по OAuth) | https://developers.sber.ru/studio/workspaces |

### Особенности российских провайдеров

**YandexGPT.** Модель задаётся не именем, а адресом вида
`gpt://<идентификатор_каталога>/yandexgpt-lite/latest`, поэтому программа отдельным
шагом спрашивает идентификатор каталога Yandex Cloud. Ключ нужен от сервисного
аккаунта с ролью `ai.languageModels.user`. Запросы идут на OpenAI-совместимый
эндпоинт `https://llm.api.cloud.yandex.net/v1`.

**GigaChat.** Авторизация двухступенчатая: ключ авторизации из личного кабинета
программа сама меняет на access-токен запросом к
`https://ngw.devices.sberbank.ru:9443/api/v2/oauth` со scope `GIGACHAT_API_PERS`
(тариф для физических лиц). Токен живёт 30 минут, кэшируется и обновляется заранее —
получать его перед каждым сообщением нельзя, у сервера авторизации есть лимит частоты.

Сервер Сбера использует сертификат НУЦ Минцифры, которого нет в стандартном хранилище.
Если появится ошибка проверки сертификата, установите его:

```bash
curl -k "https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt" >> $(python -m certifi)
```

У обоих российских провайдеров есть бесплатные лимиты: у GigaChat — freemium для
физических лиц, у Yandex Cloud — стартовый грант. Актуальные объёмы смотрите
в личном кабинете, они менялись.

## Команды в диалоге

| Команда | Действие |
|---|---|
| `/help` | справка по командам |
| `/history` | показать всю переписку целиком |
| `/stats` | подробная статистика по токенам |
| `/new` | начать диалог заново (история очищается) |
| `/exit` | выход (также `Ctrl+D`) |

`Ctrl+C` во время ожидания ответа отменяет запрос, не выходя из программы.

## Как устроен подсчёт токенов

Источник истины — поле `usage` в ответе API: после каждого запроса известно точное
число отправленных и полученных токенов. Размер диалога берётся оттуда же
(`prompt_tokens + completion_tokens` — это ровно то, что модель видела и сгенерировала).

Ещё не отправленный текст оценивается локально: через `tiktoken`, если он установлен,
иначе — эвристикой по длине строки. Поэтому цифры на экране не «прыгают» после ответа.

Из окна модели вычитается резерв под ответ (`max_tokens` запроса) — именно поэтому
«свободно» кончается раньше, чем полоса дойдёт до 100%.

Оценка «до конца диалога ≈N сообщений» = свободные токены, делённые на средний размер
одного обмена «вопрос — ответ» в этом конкретном диалоге.

## Если что-то не работает

| Что видно на экране | Что делать |
|---|---|
| `Ключ отклонён провайдером (401)` | ключ неактуален или скопирован не целиком |
| `Недостаточно средств на аккаунте провайдера (402)` | ключ рабочий, но баланс нулевой — пополнить или запустить `--demo` |
| `Вместо ответа API пришла HTML-страница` | запрос перехватил корпоративный прокси; добавьте домен провайдера в `NO_PROXY` |
| `Не удалось связаться с API` | нет сети, либо провайдер недоступен из вашего региона |
| `Не пройдена проверка TLS-сертификата` | установите сертификат НУЦ Минцифры (команда выше) |
| `В ключе есть символы вне латиницы` | при копировании попала кириллическая буква — скопируйте ключ заново |
| `Сервер не смог разобрать ключ авторизации (400)` | для GigaChat нужна вся строка Base64 из личного кабинета целиком |

## Структура

```
chat.py               точка входа
llmchat/providers.py  провайдеры, модели, размеры окон, ссылки на токены
llmchat/client.py     запросы к API (один SDK на оба провайдера) + демо-заглушка
llmchat/session.py    история диалога и учёт токенов
llmchat/tokens.py     оценка ещё не отправленного текста
llmchat/ui.py         отрисовка интерфейса на rich
llmchat/app.py        сценарий: настройка, цикл диалога, команды
run.sh                установка окружения и запуск
```

Все четыре провайдера принимают тело запроса в формате OpenAI, поэтому запросы
выполняет один SDK `openai`. Различия вынесены в описание провайдера в
`llmchat/providers.py`: адрес, формат имени модели и способ авторизации. Ровно
поэтому добавление YandexGPT и GigaChat не потребовало второго клиента — только
шаблон адреса модели для Яндекса и обмен ключа на токен для Сбера.
